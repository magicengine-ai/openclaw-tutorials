## 2. 访问控制

### 2.1 什么是访问控制？

```
访问控制 = 决定谁可以访问什么资源

核心概念：
• 主体（Subject）：用户、Agent、服务
• 客体（Object）：文件、API、配置
• 操作（Operation）：读、写、执行、删除
• 权限（Permission）：主体对客体的操作授权

示例：
用户 A → 有权限 → 读取文件 X
用户 B → 无权限 → 读取文件 X
```

### 2.2 权限模型

```
┌─────────────────────────────────────────────────────────┐
│              权限模型对比                                │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  RBAC（基于角色的访问控制）                             │
│  ──────────────────────────────                         │
│  • 用户 → 角色 → 权限                                   │
│  • 优点：管理简单，适合组织                             │
│  • 示例：管理员、普通用户、访客                         │
│                                                         │
│  ABAC（基于属性的访问控制）                             │
│  ──────────────────────────────                         │
│  • 用户属性 + 资源属性 + 环境 → 权限                    │
│  • 优点：灵活精细，适合复杂场景                         │
│  • 示例：工作时间 + 内部网络 → 允许访问                 │
│                                                         │
│  OpenClaw 推荐：RBAC + ABAC 混合                        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2.3 配置访问控制

```json
// ~/.openclaw/config.json

{
  "security": {
    "accessControl": {
      "enabled": true,
      "defaultPolicy": "deny",
      "roles": {
        "admin": {
          "permissions": ["*"]
        },
        "user": {
          "permissions": [
            "read:*",
            "write:workspace/*",
            "search:*",
            "message:send"
          ]
        },
        "guest": {
          "permissions": [
            "read:public/*",
            "search:public"
          ]
        }
      },
      "users": {
        "user@example.com": {
          "role": "user",
          "extraPermissions": ["write:reports/*"]
        }
      }
    }
  }
}
```

### 2.4 文件访问控制

## 3. 凭证管理

### 3.1 凭证类型

| 凭证类型 | 示例 | 风险等级 | 保护要求 |
|----------|------|----------|----------|
| **API Key** | OpenAI Key、阿里云 Key | 高 | 加密存储、定期更换 |
| **密码** | 登录密码、数据库密码 | 高 | 加密存储、不记录日志 |
| **Token** | OAuth Token、Session Token | 中 | 加密存储、设置过期 |
| **证书** | SSL 证书、SSH Key | 高 | 限制权限、安全存储 |
| **配置文件** | 含敏感信息的配置 | 中 | 限制访问、加密存储 |

### 3.2 凭证存储最佳实践

```
┌─────────────────────────────────────────────────────────┐
│              凭证存储最佳实践                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ✅ 推荐做法：                                          │
│                                                         │
│  1. 环境变量存储                                        │
│     export API_KEY="your-key"                           │
│     而非硬编码在配置文件中                              │
│                                                         │
│  2. 加密存储                                            │
│     使用加密工具存储敏感凭证                            │
│     如：pass、1Password、Keychain                       │
│                                                         │
│  3. 权限限制                                            │
│     chmod 600 ~/.openclaw/config.json                   │
│     只允许所有者读写                                    │
│                                                         │
│  4. 分离存储                                            │
│     凭证与代码分离                                      │
│     使用 .env 文件（不提交到版本控制）                  │
│                                                         │
│  ❌ 避免做法：                                          │
│                                                         │
│  1. 硬编码在代码中                                      │
│  2. 提交到版本控制                                      │
│  3. 明文存储在日志中                                    │
│  4. 通过不安全渠道传输                                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 4. 审计日志

### 4.1 什么是审计日志？

```
审计日志 = 记录所有安全相关操作的日志

记录内容：
• 谁（Who）：用户 ID、IP 地址
• 什么（What）：操作类型、资源
• 何时（When）：时间戳
• 结果（Result）：成功/失败

用途：
• 安全事件调查
• 合规审计
• 异常检测
• 责任追溯
```

### 4.2 日志配置

```json
{
  "logging": {
    "level": "info",
    "path": "~/.openclaw/logs",
    "maxFiles": 30,
    "maxSize": "100MB",
    "format": "json",
    "includeTimestamp": true,
    "includeUser": true,
    "includeIP": true,
    "sensitiveDataMasking": true
  },
  "auditLog": {
    "enabled": true,
    "path": "~/.openclaw/logs/audit",
    "events": [
      "login",
      "logout",
      "permission_change",
      "config_change",
      "credential_access",
      "file_access",
      "tool_execution"
    ]
  }
}
```

### 4.3 日志格式

```json
// 审计日志示例

{
  "timestamp": "2026-03-26T16:00:00+08:00",

  "resource": "~/workspace/report.md",

{

  "resource": "ls -la",

  "reason": "Command not in allowlist"
}
```

### 4.5 日志分析

```bash
# 查看最近的登录日志
grep "login" ~/.openclaw/logs/audit/*.json

# 查看失败的操作
grep "denied" ~/.openclaw/logs/audit/*.json

# 查看特定用户的操作
grep "user@example.com" ~/.openclaw/logs/audit/*.json

# 统计每天的操作数量
cat ~/.openclaw/logs/audit/*.json | jq '.timestamp' | cut -d'T' -f1 | sort | uniq -c

# 检测异常（如大量失败）
grep "denied" ~/.openclaw/logs/audit/*.json | wc -l
```

### 5.2 加密配置

```json
{
  "encryption": {
    "enabled": true,
    "algorithm": "AES-256-GCM",
    "keyRotation": {
      "enabled": true,
      "interval": "90d"
    },
    "encryptPaths": [
      "~/.openclaw/config.json",
      "~/.openclaw/credentials/*",
      "~/.openclaw/workspace/sensitive/*"
    ],
    "tls": {
      "enabled": true,
      "minVersion": "1.2",
      "certPath": "~/.openclaw/ssl/cert.pem",
      "keyPath": "~/.openclaw/ssl/key.pem"
    }
  }
}
```

### 5.3 加密工具使用

```bash
# 使用 GPG 加密文件

# 加密
gpg --cipher-algo AES256 --symmetric sensitive-file.txt

# 解密
gpg --decrypt sensitive-file.txt.gpg

# 使用 OpenSSL 加密

# 加密
openssl enc -aes-256-cbc -salt -in sensitive-file.txt -out sensitive-file.txt.enc

# 解密
openssl enc -aes-256-cbc -d -in sensitive-file.txt.enc -out sensitive-file.txt
```

## 7. 安全事件响应

### 7.1 事件分类

| 事件类型 | 描述 | 严重程度 | 响应时间 |
|----------|------|----------|----------|
| **凭证泄露** | API Key、密码泄露 | 高 | 立即 |
| **未授权访问** | 检测到未授权访问 | 高 | 1 小时内 |
| **数据泄露** | 敏感数据被获取 | 高 | 立即 |
| **异常登录** | 可疑登录尝试 | 中 | 4 小时内 |
| **配置篡改** | 配置文件被修改 | 中 | 4 小时内 |
| **服务异常** | 服务不可用或异常 | 低 | 24 小时内 |

## 9. 本篇总结

### 📌 核心要点

1. **访问控制**：RBAC+ABAC 混合模型，限制文件和工具访问
