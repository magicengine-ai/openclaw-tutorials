## 3. 核心组件详解

### 3.1 Gateway（网关）

**职责：**
- 接收来自各个 Channel 的消息
- 将消息路由到正确的会话
- 管理会话状态
- 调度任务执行

**类比：** 就像公司的"前台 + 总机"
- 接待所有来电（消息）
- 转接给对应的人（会话）
- 记录谁在什么时候打了电话（会话管理）

### 3.2 Agent 核心

**职责：**
- 理解用户意图
- 决定使用哪些工具
- 执行工具调用
- 组织返回结果

**核心流程：**
```
1. 接收用户消息
2. 读取上下文（历史对话、记忆）
3. 发送给 AI 模型
4. AI 模型决定调用工具
5. 执行工具
6. 将结果返回给 AI 模型
7. AI 模型生成最终回复
8. 发送回复给用户
```

### 3.3 工具层

**每个工具都有：**
- **名称**：如 `read`, `write`, `web_search`
- **描述**：说明这个工具是做什么的
- **参数**：需要传入什么信息
- **返回值**：会返回什么结果

**示例工具定义：**
```json
{
  "name": "web_search",
  "description": "Search the web using Brave Search API",
  "parameters": {
    "query": "搜索关键词",
    "count": "返回结果数量 (1-10)",
    "freshness": "时间过滤 (day/week/month)"
  }
}
```

## 4. 完整流程演示

让我们跟踪一条消息的完整旅程：

### 场景：你说"帮我查一下今天的 AI 新闻"

#### 步骤 1：消息接收

```
[飞书/Telegram/命令行] 
    │
    ▼
┌─────────────────────────┐
│ Gateway 收到消息         │
│ 消息内容："帮我查一下    │
│ 今天的 AI 新闻"           │
│ 发送者：ou_xxx          │
│ 时间：2026-03-25 21:00 │
└─────────────────────────┘
```

#### 步骤 2：会话查找

```
Gateway 检查：
- 这个用户有现有会话吗？→ 有，session_123
- 加载会话历史（最近 10 条消息）
- 加载用户配置（偏好设置、允许的工具）
```

#### 步骤 3：构建 Prompt

```
系统把以下内容组合成 Prompt：

┌────────────────────────────────────────┐
│ 系统提示词（System Prompt）             │
│ "你是一个个人助手，运行在 OpenClaw..." │
├────────────────────────────────────────┤
│ 可用工具列表                           │
│ - read: 读取文件                        │
│ - write: 写入文件                       │
│ - web_search: 搜索网络                  │
│ ...                                    │
├────────────────────────────────────────┤
│ 对话历史                               │
│ 用户：早上好                           │
│ 助手：早上好！有什么可以帮你的？        │
├────────────────────────────────────────┤
│ 当前消息                               │
│ 用户：帮我查一下今天的 AI 新闻          │
└────────────────────────────────────────┘
```

#### 步骤 4：AI 模型决策

```
Prompt 发送给 AI 模型 (Qwen/Claude/GPT)

AI 模型思考：
"用户想要 AI 新闻 → 需要搜索网络 → 使用 web_search 工具"

AI 模型返回：
{
  "tool_calls": [
    {
      "name": "web_search",
      "arguments": {
        "query": "AI 人工智能 最新新闻",
        "count": 5,
        "freshness": "day"
      }
    }
  ]
}
```

#### 步骤 5：工具执行

```
OpenClaw 收到工具调用请求
    │
    ▼
执行 web_search 工具
    │
    ▼
调用 Brave Search API
    │
    ▼
返回搜索结果
```

#### 步骤 6：结果处理

```
搜索结果返回给 AI 模型：
[
  {
    "title": "OpenAI 发布新模型...",
    "url": "https://...",
    "description": "..."
  },
  ...
]

AI 模型思考：
"收到搜索结果了，现在整理成用户友好的格式"

AI 模型生成回复：
"好的，我找到了今天的 AI 新闻：

1. OpenAI 发布新模型...
2. Google 更新 AI 系统...
3. ...

需要我详细展开哪一条吗？"
```

#### 步骤 7：发送回复

```
OpenClaw 将回复发送到原渠道（飞书/Telegram）
    │
    ▼
用户收到消息
```

## 5. 工具调用的细节

### 5.1 工具如何被选择？

**AI 模型基于：**
1. 用户意图（从消息中理解）
2. 工具描述（每个工具的功能说明）
3. 上下文（之前的对话）

**示例：**
```
用户说："帮我读一下今天的会议记录"

AI 模型分析：
- "读" → 文件操作
- "会议记录" → 可能是文件
- 结论：使用 read 工具
```

### 5.2 工具调用格式

**Function Calling 格式：**
```json
{
  "name": "read",
  "arguments": {
    "path": "/home/user/meetings/2026-03-25.md"
  }
}
```

**工具执行后返回：**
```json
{
  "result": "会议内容...",
  "error": null
}
```

### 5.3 多工具调用

复杂任务可能需要多个工具：

```
用户："帮我查一下 AI 新闻，然后保存到文件里"

流程：
1. web_search → 获取新闻
2. write → 保存到文件
3. message → 发送通知

AI 模型会依次调用这些工具
```

## 6. 上下文管理

### 6.1 短期上下文（会话内）

```
┌─────────────────────────────────────┐
│ 当前会话历史                         │
│                                     │
│ [用户] 早上好                        │
│ [助手] 早上好！有什么可以帮你的？    │
│ [用户] 帮我查一下 AI 新闻             │
│ [助手] 好的，找到了...              │
│ [用户] 保存到文件里                  │
│ [助手] 已保存到 news.md             │
└─────────────────────────────────────┘

这个历史会发送给 AI 模型，让它知道之前的对话
```

### 6.2 长期上下文（记忆）

```
MEMORY.md 文件：
- 用户偏好：喜欢简洁的回复
- 重要信息：在 XX 公司工作
- 项目信息：正在做 YY 项目

这些会在需要时被检索并发送给 AI 模型
```

### 6.3 上下文窗口限制

**问题：** AI 模型有 token 限制（如 128K）

**解决方案：**
- 只发送最近的对话历史
- 使用记忆检索（只检索相关的）
- 长内容截断/摘要

## 7. 错误处理

### 7.1 工具调用失败

```
场景：web_search API 超时

处理流程：
1. 捕获错误
2. 返回错误信息给 AI 模型
3. AI 模型决定：
   - 重试
   - 使用备用方案
   - 告知用户失败
```

### 7.2 AI 模型调用失败

```
场景：AI API 返回错误

处理流程：
1. 捕获错误
2. 记录日志
3. 返回友好错误消息给用户
4. 建议用户重试或检查配置
```

## 8. 安全机制

### 8.1 工具权限控制

```
config.json 配置：
{
  "tools": {
    "allow": ["read", "write", "web_search"],
    "deny": ["exec", "browser"]
  }
}

被 deny 的工具不会被发送给 AI 模型
```

### 8.2 命令执行限制

```
exec 工具的安全模式：
- deny: 完全禁止
- allowlist: 只允许特定命令
- full: 完全允许（危险！）
```

### 8.3 文件访问限制

```
- 默认只能访问 workspace 目录
- 访问其他目录需要明确配置
- 敏感文件（密码、密钥）需要额外保护
```

## 9. 性能优化

### 9.1 工具调用优化

**问题：** 频繁调用工具会慢

**优化：**
- 批量调用（一次搜索多个关键词）
- 缓存结果（相同查询不重复执行）
- 异步执行（不阻塞主流程）

### 9.2 上下文优化

**问题：** 长上下文消耗 token

**优化：**
- 智能截断（保留重要部分）
- 摘要压缩（用摘要代替原文）
- 外部记忆（存文件里，需要时再读）

## 12. 本篇总结

### 📌 核心要点

1. **Gateway** 是消息入口，负责路由和会话管理
2. **Agent 核心** 包含 AI 模型和工具调度器
3. **工具调用流程**：理解意图 → 选择工具 → 执行 → 处理结果
4. **上下文管理** 对保持对话连贯性至关重要
5. **安全机制** 保护你的数据和系统
