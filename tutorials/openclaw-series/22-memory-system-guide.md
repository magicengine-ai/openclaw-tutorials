## 2. 短期记忆

### 2.1 什么是短期记忆？

```
短期记忆 = 当前会话的对话历史

特点：
• 自动维护，无需手动操作
• 受模型上下文窗口限制（如 8K/16K/32K tokens）
• 会话结束后消失
• 用于保持对话连贯性
```

### 2.2 短期记忆工作原理

```
对话流程中的短期记忆：

用户：你好，我叫小明
  ↓
Agent: 你好小明，有什么可以帮你的？
  ↓
用户：我想知道今天的天气
  ↓
Agent: [记得用户叫小明] 好的，帮你查询...
  ↓
用户：我住在北京
  ↓
Agent: [记得用户叫小明，住北京] 北京今天...

短期记忆内容：
1. 用户叫小明
2. 用户想知道天气
3. 用户住在北京
4. 当前任务是查询天气
```

### 2.3 管理短期记忆

```bash
# 查看当前会话历史
openclaw sessions history

# 查看指定会话历史
openclaw sessions history --sessionKey xxx --limit 50

# 清理会话历史（开始新对话）
openclaw sessions clear
```

### 2.4 短期记忆优化

```
✅ 推荐做法：

1. 保持对话聚焦
   - 一个会话专注于一个主题
   - 避免频繁切换话题

2. 重要信息及时固化
   - 重要信息写入长期记忆
   - 不要依赖短期记忆

3. 定期清理
   - 完成任务后开始新会话
   - 避免历史过长影响性能

4. 会话标签
   - 给会话添加标签便于查找
   - 如：项目 A、个人事务等
```

## 3. 长期记忆

### 3.1 什么是长期记忆？

```
长期记忆 = 持久化存储的重要信息

特点：
• 存储在 MEMORY.md 和 memory/*.md 文件中
• 会话结束后依然保留
• 支持语义搜索
• 需要主动写入和管理
```

### 3.2 记忆文件结构

```
~/.openclaw/workspace/
├── MEMORY.md              # 主记忆文件
└── memory/                # 分类记忆目录
    ├── 2026-03-26.md      # 每日记忆
    ├── projects.md        # 项目记忆
    ├── preferences.md     # 偏好记忆
    └── contacts.md        # 联系人记忆
```

### 3.3 MEMORY.md 格式

```markdown
# 长期记忆

## 个人信息
- 姓名：小明
- 城市：北京
- 职业：软件工程师
- 时区：Asia/Shanghai

## 项目
- 项目 A：电商平台开发（2026-03 开始）
- 项目 B：数据分析系统（2026-02 开始）

## 偏好
- 喜欢简洁的回复风格
- 偏好使用飞书沟通
- 早上 9 点开始工作

## 重要决定
- 2026-03-25：决定使用 OpenClaw 作为个人助手
- 2026-03-20：决定学习 TypeScript

## 待追踪事项
- 每周检查股票投资组合
- 每月 review 项目进度
```

### 3.4 写入长期记忆

**对话示例：**

```
你：记住我叫小明，住在北京

Agent: 好的，我已经记住了。

✅ 已写入长期记忆：
- 姓名：小明
- 城市：北京

以后我会记得这些信息。
```

**对应的工具调用：**

```json
{
  "name": "memory_write",
  "arguments": {
    "path": "MEMORY.md",
    "content": "## 个人信息\n- 姓名：小明\n- 城市：北京\n"
  }
}
```

### 3.5 检索长期记忆

**对话示例：**

```
你：你还记得我住在哪里吗？

Agent: 让我查一下记忆...

📋 记忆检索结果：

根据长期记忆，你住在北京。

这个信息是在 2026-03-26 记录的。
```

**对应的工具调用：**

```json
{
  "name": "memory_search",
  "arguments": {
    "query": "用户居住城市",
    "maxResults": 5,
    "minScore": 0.5
  }
}
```

### 3.6 记忆搜索参数

```json
{
  "query": "搜索关键词",      // 必填：语义搜索关键词
  "maxResults": 10,           // 可选：最大返回结果数
  "minScore": 0.5,            // 可选：最小相关度分数
  "path": "MEMORY.md"         // 可选：指定搜索文件
```

## 4. 记忆管理工具

### 4.1 记忆写入工具

```typescript
// 写入记忆的示例代码

const writeMemory = async (content: string, path: string = 'MEMORY.md') => {
  // 读取现有记忆
  const existing = await readFile(path);
  
  // 追加新内容
  const updated = existing + '\n\n' + content;
  
  // 写回文件
  await writeFile(path, updated);
  
  return '记忆已更新';
};

// 使用示例
await writeMemory('- 偏好：喜欢简洁的回复', 'MEMORY.md');
```

### 4.2 记忆搜索工具

```typescript
// 记忆搜索的示例代码

const searchMemory = async (query: string, options: any = {}) => {
  const { maxResults = 10, minScore = 0.5 } = options;
  
  // 语义搜索实现
  const results = await semanticSearch(query, {
    maxResults,
    minScore
  });
  
  return results;
};

// 使用示例
const results = await searchMemory('用户偏好', { maxResults: 5 });
```

### 4.3 记忆更新工具

```typescript
// 更新记忆的示例代码

const updateMemory = async (key: string, value: string) => {
  // 读取记忆
  const memory = await readFile('MEMORY.md');
  
  // 查找并替换
  const updated = memory.replace(
    new RegExp(`- ${key}:.*`),
    `- ${key}: ${value}`
  );
  
  // 写回
  await writeFile('MEMORY.md', updated);
  
  return '记忆已更新';
};

// 使用示例
await updateMemory('城市', '上海');
```

### 4.4 记忆删除工具

```typescript
// 删除记忆的示例代码

const deleteMemory = async (key: string) => {
  const memory = await readFile('MEMORY.md');
  
  // 删除指定行
  const updated = memory
    .split('\n')
    .filter(line => !line.includes(key))
    .join('\n');
  
  await writeFile('MEMORY.md', updated);
  
  return '记忆已删除';
};

// 使用示例
await deleteMemory('旧项目');
```

```
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 5.2 记忆写入原则

```
✅ 应该写入记忆的信息：

1. 个人基本信息
   - 姓名、城市、职业
   - 联系方式
   - 重要日期

2. 偏好和习惯
   - 沟通偏好
   - 工作习惯
   - 生活方式

3. 长期项目
   - 项目名称和目标
   - 关键里程碑
   - 重要决策

4. 重要决定
   - 职业决定
   - 投资决策
   - 生活改变

❌ 不应该写入记忆的信息：

1. 临时信息
   - 一次性任务
   - 短期安排

2. 敏感信息
   - 密码和密钥
   - 财务详情
   - 隐私数据

3. 过多细节
   - 每次对话详情
   - 琐碎信息
```

### 5.3 记忆更新策略

```
✅ 推荐做法：

1. 定期 review
   - 每周检查记忆文件
   - 更新过时信息
   - 删除无用内容

2. 版本控制
   - 重要变更添加日期
   - 保留历史记录
   - 便于追溯

3. 结构化存储
   - 使用清晰分类
   - 统一格式
   - 便于搜索

4. 适度冗余
   - 关键信息多处存储
   - 提高检索成功率
   - 但避免过度重复
```

### 5.4 记忆检索技巧

```
✅ 提高检索成功率：

1. 使用语义关键词
   - 不用精确匹配
   - 用相关概念搜索

2. 分层搜索
   - 先搜索主记忆文件
   - 再搜索分类记忆

3. 设置合理阈值
   - minScore 不要太高
   - 避免漏掉相关信息

4. 结果验证
   - 检查检索结果相关性
   - 必要时人工确认
```

## 7. 记忆系统配置

### 7.1 配置文件

```json
// ~/.openclaw/config.json

{
  "memory": {
    "enabled": true,
    "path": "~/.openclaw/workspace/memory",
    "mainFile": "MEMORY.md",
    "maxSnippets": 10,
    "minScore": 0.5,
    "autoSave": true,
    "categories": [
      "projects",
      "contacts",
      "preferences"
    ]
  }
}
```

### 7.2 配置参数说明

| 参数 | 说明 | 默认值 | 推荐值 |
|------|------|--------|--------|
| `enabled` | 是否启用记忆 | true | true |
| `path` | 记忆文件路径 | ~/workspace/memory | 同默认 |
| `mainFile` | 主记忆文件名 | MEMORY.md | 同默认 |
| `maxSnippets` | 最大检索结果数 | 10 | 5-15 |
| `minScore` | 最小相关度分数 | 0.5 | 0.4-0.7 |
| `autoSave` | 自动保存重要信息 | true | true |

## 8. 常见问题

### 8.1 记忆不生效

```
问题：Agent 不记得之前说过的话

可能原因：
1. 记忆未正确写入
2. 搜索阈值太高
3. 记忆文件格式错误

解决方案：
- 检查 MEMORY.md 是否存在
- 降低 minScore 阈值
- 验证文件格式
```

### 8.2 记忆过多

```
问题：记忆文件太大，检索慢

可能原因：
1. 存储了太多信息
2. 没有定期清理
3. 分类不合理

解决方案：
- 定期清理过时信息
- 使用分类记忆文件
- 归档旧记忆
```

### 8.3 记忆冲突

```
问题：记忆中有矛盾信息

可能原因：
1. 多次更新未覆盖
2. 不同来源的信息
3. 时间戳缺失

解决方案：
- 添加时间戳
- 更新时覆盖旧信息
- 定期 review 和整理
```
