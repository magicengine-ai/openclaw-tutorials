## 2. Cron 定时任务

### 2.1 什么是 Cron？

```
Cron = 定时任务调度器

起源：Unix/Linux 系统的传统定时任务工具

OpenClaw 中的 Cron：
• 基于标准 Cron 表达式
• 支持多种调度模式
• 可执行各种任务
• 独立会话运行
```

### 2.2 Cron 表达式详解

```
┌─────────────────────────────────────────────────────────┐
│              Cron 表达式格式                              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  标准格式（5 位）：                                      │
│  ┌───────────── 分钟 (0-59)                             │
│  │ ┌───────────── 小时 (0-23)                           │
│  │ │ ┌───────────── 日期 (1-31)                         │
│  │ │ │ ┌───────────── 月份 (1-12)                       │
│  │ │ │ │ ┌───────────── 星期 (0-6, 0=周日)              │
│  │ │ │ │ │                                               │
│  * * * * *                                               │
│                                                         │
│  示例：                                                  │
│  0 8 * * *   → 每天早上 8 点                             │
│  0 9 * * 1   → 每周一上午 9 点                           │
│  */30 * * * * → 每 30 分钟                               │
│  0 0 1 * *   → 每月 1 号零点                             │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2.3 Cron 特殊符号

| 符号 | 含义 | 示例 | 说明 |
|------|------|------|------|
| `*` | 任意值 | `* * * * *` | 每分钟 |
| `,` | 分隔多个值 | `0 9,17 * * *` | 9 点和 17 点 |
| `-` | 范围 | `0 9-17 * * *` | 9 点到 17 点每小时 |
| `/` | 间隔 | `*/30 * * * *` | 每 30 分钟 |

### 2.4 常用 Cron 表达式

```
┌─────────────────────────────────────────────────────────┐
│              常用 Cron 表达式速查表                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  每日任务：                                             │
│  0 8 * * *    → 每天早上 8 点                           │
│  0 12 * * *   → 每天中午 12 点                          │
│  0 18 * * *   → 每天下午 6 点                           │
│  0 22 * * *   → 每天晚上 10 点                          │
│                                                         │
│  每周任务：                                             │
│  0 9 * * 1    → 每周一上午 9 点                         │
│  0 9 * * 1-5  → 每工作日（周一到五）上午 9 点           │
│  0 10 * * 6   → 每周六上午 10 点                        │
│  0 10 * * 0   → 每周日上午 10 点                        │
│                                                         │
│  每月任务：                                             │
│  0 9 1 * *    → 每月 1 号上午 9 点                      │
│  0 9 15 * *   → 每月 15 号上午 9 点                     │
│  0 9 L * *    → 每月最后一天上午 9 点                   │
│                                                         │
│  间隔任务：                                             │
│  */5 * * * *  → 每 5 分钟                               │
│  */30 * * * * → 每 30 分钟                              │
│  0 */2 * * *  → 每 2 小时                               │
│  0 */4 * * *  → 每 4 小时                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2.5 创建 Cron 任务

**对话示例：**

```
你：帮我设置每天早上 8 点推送新闻

Agent: 好的，我来创建定时任务...

✅ Cron 任务已创建

📋 任务详情：
- 名称：每日新闻推送
- 时间：每天早上 8:00
- Cron: 0 8 * * *
- 任务：搜索最新新闻并发送到飞书
- 状态：已启用

明天早上 8 点开始执行。
```

**对应的工具调用：**

```json
{
  "name": "cron",
  "action": "add",
  "job": {
    "name": "每日新闻推送",
    "schedule": {
      "kind": "cron",
      "expr": "0 8 * * *",
      "tz": "Asia/Shanghai"
    },
    "payload": {
      "kind": "systemEvent",
      "text": "搜索今天的最新新闻并发送给用户"
    },
    "sessionTarget": "main",
    "enabled": true
  }
}
```

### 2.6 Cron 任务配置

```json
{
  "name": "任务名称",
  "schedule": {
    "kind": "cron",           // 调度类型：cron/every/at
    "expr": "0 8 * * *",      // Cron 表达式
    "tz": "Asia/Shanghai"     // 时区
  },
  "payload": {
    "kind": "systemEvent",    // 负载类型
    "text": "任务描述"
  },
  "sessionTarget": "main",    // 目标会话：main/isolated
  "enabled": true,            // 是否启用
  "delivery": {               // 交付方式（可选）
    "mode": "announce",       // announce/webhook/none
    "channel": "feishu"       // 通知渠道
  }
}
```

## 3. Heartbeat 机制

### 3.1 什么是 Heartbeat？

```
Heartbeat = 心跳机制 / 定期轮询

工作原理：
• OpenClaw 定期（如每 30 分钟）触发一次心跳
• 心跳时检查 HEARTBEAT.md 中的任务
• 执行需要定期检查的任务
• 适合批量检查和周期性任务

与 Cron 的区别：
• Cron：精确时间，独立任务
• Heartbeat：相对时间，与主会话集成
```

### 3.2 HEARTBEAT.md 配置

```markdown
# HEARTBEAT.md

# 保持此文件为空（或只包含注释）可跳过心跳 API 调用。

# 在下方添加任务，让 Agent 定期检查某些事项。

# 每日检查
- [ ] 检查未读邮件
- [ ] 查看日历事件
- [ ] 检查天气（如果可能外出）

# 每周检查
- [ ] review 项目进度
- [ ] 检查投资组合
```

### 3.3 Heartbeat 工作流程

```
┌─────────────────────────────────────────────────────────┐
│              Heartbeat 工作流程                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 系统触发心跳（如每 30 分钟）                         │
│         ↓                                               │
│  2. 读取 HEARTBEAT.md                                   │
│         ↓                                               │
│  3. 检查任务列表                                        │
│         ↓                                               │
│  4. 执行需要检查的任务                                  │
│         ↓                                               │
│  5. 如有需要，通知用户                                  │
│         ↓                                               │
│  6. 记录执行结果                                        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.4 Heartbeat 使用示例

```
场景：定期检查重要事项

HEARTBEAT.md 配置：
# 每 30 分钟检查
- 检查是否有紧急邮件
- 检查服务器状态

# 每天检查（通过记录上次检查时间）
- 检查日历（如有 24 小时内事件则通知）
- 检查天气（如明天可能下雨则通知）

Agent 行为：
• 心跳时自动检查
• 只有需要通知时才打扰用户
• 正常时回复 HEARTBEAT_OK
```

### 5.2 启用/禁用任务

```bash
# 禁用任务
openclaw cron update --jobId job-001 --patch '{"enabled": false}'

# 启用任务
openclaw cron update --jobId job-001 --patch '{"enabled": true}'

# 查看任务状态
openclaw cron status --jobId job-001
```

### 5.3 手动触发任务

```bash
# 立即执行任务（不等待定时）
openclaw cron run --jobId job-001

# 强制运行（即使已禁用）
openclaw cron run --jobId job-001 --runMode force
```

## 6. 最佳实践

### 6.1 任务设计

```
✅ 推荐做法：

1. 任务单一职责
   - 一个任务做一件事
   - 避免复杂依赖

2. 合理设置频率
   - 不要过于频繁
   - 考虑 API 限流

3. 设置超时时间
   - 防止无限期运行
   - 默认 5-10 分钟

4. 添加错误处理
   - 失败时通知
   - 设置重试策略
```

### 6.2 资源管理

```
✅ 推荐做法：

1. 限制并发数量
   - 同时运行的任务不超过 3 个
   - 避免资源竞争

2. 错峰执行
   - 避免所有任务同时运行
   - 分散执行时间

3. 定期清理
   - 清理过期的执行历史
   - 释放存储空间

4. 监控资源使用
   - 检查 CPU/内存使用
   - 调整任务频率
```

### 6.3 日志和监控

```
✅ 推荐做法：

1. 记录执行日志
   - 开始时间、结束时间
   - 执行结果、错误信息

2. 设置告警
   - 连续失败告警
   - 超时告警

3. 定期检查
   - 每周检查任务状态
   - 确认正常运行

4. 版本控制
   - 任务配置纳入版本控制
   - 便于追溯和回滚
```

## 7. 常见问题

### 7.1 任务不执行

```
问题：Cron 任务到时间不执行

可能原因：
1. 任务已禁用
2. Cron 表达式错误
3. 时区设置错误
4. Gateway 未运行

解决方案：
- 检查任务状态：openclaw cron list
- 验证 Cron 表达式
- 确认时区设置
- 检查 Gateway 状态
```

### 7.2 任务执行失败

```
问题：任务执行时报错

可能原因：
1. API 调用失败
2. 权限不足
3. 资源不足
4. 网络问题

解决方案：
- 查看执行日志
- 检查 API 凭证
- 检查系统资源
- 设置重试机制
```

### 7.3 重复执行

```
问题：任务被重复执行

可能原因：
1. 多个 Gateway 实例
2. 配置同步问题
3. 时钟不同步

解决方案：
- 确保单实例运行
- 同步配置文件
- 校准时钟
```
