## 1. 子 Agent 系统总览

### 1.1 什么是子 Agent？

```
┌─────────────────────────────────────────────────────────┐
│              子 Agent 系统                               │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  子 Agent = 由主 Agent 创建和管理的独立 Agent 实例        │
│                                                         │
│  类比理解：                                             │
│  • 经理（主 Agent）→ 分配任务给员工（子 Agent）         │
│  • 导演（主 Agent）→ 指导演员（子 Agent）表演           │
│  • 指挥（主 Agent）→ 协调乐手（子 Agent）演奏           │
│                                                         │
│  为什么需要子 Agent？                                   │
│  • 复杂任务需要分工协作                                 │
│  • 并行处理提高效率                                     │
│  • 专业化分工（每个 Agent 擅长不同领域）                │
│  • 隔离风险（子 Agent 失败不影响主 Agent）              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 1.2 主 Agent vs 子 Agent

| 特性 | 主 Agent | 子 Agent |
|------|----------|----------|
| **创建者** | 用户 | 主 Agent |
| **任务来源** | 用户直接分配 | 主 Agent 分配 |
| **独立性** | 完全独立 | 依赖主 Agent |
| **生命周期** | 长期运行 | 任务完成后结束 |
| **资源访问** | 完整权限 | 受限权限 |
| **结果处理** | 汇总子 Agent 结果 | 返回结果给主 Agent |

## 2. Spawn 子 Agent

### 2.1 基本用法

**对话示例：**

```
你：帮我研究一下最新的 AI 技术趋势

主 Agent: 好的，这个任务比较复杂，我来创建一个研究 Agent 专门处理...

🤖 已创建子 Agent：research-agent-001
任务：研究最新的 AI 技术趋势
预计时间：5-10 分钟

子 Agent 正在工作中...
完成后我会汇总结果给你。
```

**对应的工具调用：**

```json
{
  "name": "sessions_spawn",
  "arguments": {
    "task": "研究最新的 AI 技术趋势，包括大模型、多模态、Agent 等方向",
    "runtime": "subagent",
    "mode": "run",
    "label": "research-agent-001"
  }
}
```

### 2.2 Spawn 参数详解

```json
{
  "task": "任务描述",           // 必填：子 Agent 要完成的任务
  "runtime": "subagent",       // 运行环境：subagent 或 acp
  "mode": "run",               // 模式：run(一次性) 或 session(持久)
  "label": "agent-label",      // 可选：Agent 标签/名称
  "agentId": "specific-agent", // 可选：指定 Agent ID
  "timeoutSeconds": 300,       // 可选：超时时间（秒）
  "model": "qwen-plus",        // 可选：指定使用的模型
  "thinking": "on",            // 可选：思考模式
  "cleanup": "delete"          // 可选：完成后清理（delete/keep）
}
```

### 2.3 运行模式

```
┌─────────────────────────────────────────────────────────┐
│              两种运行模式                                │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  mode: "run"（一次性模式）                              │
│  ──────────────────────────────                         │
│  • 任务完成后自动结束                                   │
│  • 结果返回给主 Agent                                   │
│  • 适合独立任务                                         │
│  • 资源自动释放                                         │
│                                                         │
│  mode: "session"（持久模式）                            │
│  ──────────────────────────────                         │
│  • 长期运行，等待后续指令                               │
│  • 可以多次交互                                         │
│  • 适合持续监控或长期任务                               │
│  • 需要手动结束                                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 3. 多 Agent 任务分发

### 3.1 任务分解策略

```
场景：完成一份市场研究报告

❌ 不好的做法：
创建一个 Agent 完成所有工作

✅ 好的做法：
分解为多个子任务，分配给不同 Agent

主 Agent
├── 研究 Agent（收集市场数据）
├── 分析 Agent（分析竞争格局）
├── 写作 Agent（撰写报告）
└── 审查 Agent（审核质量）
```

### 3.2 实战：市场研究报告

```
你：帮我完成一份 AI 行业市场研究报告

主 Agent: 好的，这是一个复杂任务，我来协调多个 Agent 完成...

📋 任务分解：

步骤 1: 创建研究 Agent
🤖 research-agent-001
任务：收集 AI 行业市场数据
- 市场规模
- 主要玩家
- 发展趋势

步骤 2: 创建分析 Agent
🤖 analysis-agent-001
任务：分析竞争格局
- SWOT 分析
- 市场定位
- 机会威胁

步骤 3: 创建写作 Agent
🤖 writing-agent-001
任务：撰写研究报告
- 整合研究数据
- 整合分析结果
- 生成报告文档

步骤 4: 创建审查 Agent
🤖 review-agent-001
任务：审核报告质量
- 数据准确性
- 逻辑连贯性
- 格式规范性

⏳ 所有 Agent 正在并行工作中...
预计完成时间：15-20 分钟
```

### 3.3 任务依赖管理

```
有些任务有先后依赖关系：

┌─────────────────────────────────────────────────────────┐
│              任务依赖图                                  │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [研究 Agent] ──────┐                                   │
│       │             │                                   │
│       ▼             │                                   │
│  [分析 Agent] ──────┼──→ [写作 Agent] ──→ [审查 Agent] │
│       │             │                                   │
│       ▼             │                                   │
│  [数据 Agent] ──────┘                                   │
│                                                         │
│  依赖关系：                                             │
│  • 分析需要研究结果                                     │
│  • 写作需要分析和数据                                   │
│  • 审查需要写作完成                                     │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**实现方式：**

```typescript
// 主 Agent 协调逻辑

// 步骤 1: 并行启动无依赖的任务
const researchAgent = await spawn({
  task: '收集市场数据',
  mode: 'run'
});

const dataAgent = await spawn({
  task: '收集行业数据',
  mode: 'run'
});

// 步骤 2: 等待依赖任务完成
const researchResult = await waitForCompletion(researchAgent);
const dataResult = await waitForCompletion(dataAgent);

// 步骤 3: 启动依赖前序结果的任务
const analysisAgent = await spawn({
  task: `基于以下数据进行分析：${researchResult}`,
  mode: 'run'
});

// 步骤 4: 继续后续任务...
```

```
analysis-agent-001:
✅ 完成 - 返回分析结果（3000 字）

writing-agent-001:
✅ 完成 - 返回报告初稿（10000 字）

review-agent-001:
✅ 完成 - 返回审核意见（500 字）
```

### 4.2 结果整合

```
主 Agent 整合所有结果：

📋 最终报告结构：

# AI 行业市场研究报告

## 执行摘要
（由主 Agent 编写）

（来自 research-agent-001）

## 竞争格局
（来自 analysis-agent-001）

```

### 4.3 冲突解决

```
当子 Agent 结果有冲突时：

场景：两个 Agent 给出不同的市场数据

research-agent-001: 市场规模 1000 亿
data-agent-001: 市场规模 800 亿

主 Agent 的处理：
1. 检查数据来源
2. 对比数据口径
3. 选择更可靠的数据
4. 在报告中标注差异

最终输出：
"根据 XX 数据，市场规模约 800-1000 亿
（差异源于统计口径不同）"
```

## 5. 管理子 Agent

### 5.1 查看子 Agent 状态

```bash
# 查看运行中的子 Agent
openclaw subagents list

# 输出示例：
┌─────────────────────────────────────────┐
│  运行中的子 Agent                        │
├─────────────────────────────────────────┤
│  ID: agent-001                          │
│  任务：收集市场数据                     │
│  状态：运行中                           │
│  已运行：5 分钟                          │
│                                         │
│  ID: agent-002                          │
│  任务：分析竞争格局                     │
│  状态：运行中                           │
│  已运行：3 分钟                          │
└─────────────────────────────────────────┘
```

### 5.2 与子 Agent 交互

```bash
# 给子 Agent 发送新指令
openclaw subagents steer --target agent-001 --message "重点关注中国市场"

# 获取子 Agent 的中间结果
openclaw subagents get --target agent-001
```

### 5.3 终止子 Agent

```bash
# 终止单个子 Agent
openclaw subagents kill --target agent-001

# 终止所有子 Agent
openclaw subagents kill --all

# 确认提示：
⚠️ 确定要终止这个 Agent 吗？
   未完成的任务将会丢失。
   输入 yes 确认
```

### 5.4 查看子 Agent 历史

```bash
# 查看子 Agent 的运行历史
openclaw sessions history --sessionKey agent-001

# 查看最近创建的子 Agent
openclaw subagents list --recentMinutes 60
```

## 7. 最佳实践

### 7.1 任务分配原则

```
┌─────────────────────────────────────────────────────────┐
│              任务分配原则                                │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ✅ 适合子 Agent 的任务：                                │
│  • 独立的、可并行的任务                                 │
│  • 需要专业知识的任务                                   │
│  • 耗时的研究或分析任务                                 │
│  • 需要多次迭代的任务                                   │
│                                                         │
│  ❌ 不适合子 Agent 的任务：                              │
│  • 过于简单的任务（开销大于收益）                       │
│  • 需要即时响应的任务                                   │
│  • 涉及敏感信息的任务                                   │
│  • 需要人类判断的任务                                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 7.2 资源管理

```
✅ 推荐做法：

1. 限制并发数量
   - 同时运行的子 Agent 不超过 5 个
   - 避免资源耗尽

2. 设置超时时间
   - 每个子 Agent 设置合理的 timeout
   - 防止无限期等待

3. 及时清理
   - 任务完成后 cleanup: delete
   - 释放系统资源

4. 监控资源使用
   - 定期检查内存和 CPU
   - 调整并发策略
```

### 7.3 错误处理

```
✅ 推荐做法：

1. 子 Agent 失败不影响主 Agent
   try {
     const result = await spawn(...);
   } catch (error) {
     // 记录错误，继续其他任务
   }

2. 重试机制
   - 失败的任务可以重试 1-2 次
   - 设置重试间隔

3. 降级方案
   - 关键任务有备选方案
   - 子 Agent 失败时主 Agent 接管

4. 错误通知
   - 重要错误通知用户
   - 提供错误详情和建议
```

## 9. 常见问题

### 9.1 性能问题

```
问题：子 Agent 运行很慢

可能原因：
1. 并发太多，资源不足
2. 模型响应慢
3. 任务太复杂

解决方案：
- 减少并发数量
- 使用更快的模型
- 进一步分解任务
```

### 9.2 通信问题

```
问题：子 Agent 无法接收指令

可能原因：
1. Agent 已结束
2. 会话 ID 错误
3. 网络问题

解决方案：
- 检查 Agent 状态
- 确认 sessionKey 正确
- 重新创建 Agent
```

### 9.3 结果不一致

```
问题：不同 Agent 给出矛盾结果

可能原因：
1. 数据来源不同
2. 分析方法不同
3. 模型随机性

解决方案：
- 统一数据来源
- 标准化分析方法
- 主 Agent 协调裁决
```
